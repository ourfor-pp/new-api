# 生产拓扑与操作清单

## 已知拓扑

- 生产由 Docker Compose 管理，`new-api` 数据目录独立持久化到宿主机。
- 当前仍使用 SQLite；数据库文件、备份和镜像构建目录相互分离。
- manager、new-api、Nginx 是不同服务。发布 new-api 不应顺带重建 manager。
- 容器可能没有 shell；所有命令都应先通过只读探测确认可用性。

主机地址和凭据不写入仓库。执行时从当前授权环境解析目标，并在命令前显示非敏感目标摘要。

## 候选与回滚准备

1. 对上传前后的同一镜像归档比较 SHA-256。Docker 版本或存储后端不同时，加载后的 image ID 和显示大小可能变化；再比较 RootFS diff IDs、入口/工作目录/非敏感环境配置、版本、提交标签和 `/new-api` 二进制 SHA-256。
2. 复制活动 Compose 为带时间戳的回滚文件；从活动文件生成候选文件，只允许精确替换一次 `new-api` 镜像引用。使用 `docker compose config --services` 和 `--images` 验证候选，不输出环境变量值。
3. 切换时先把已验证候选提升为活动 Compose，再执行 `docker compose up -d --no-deps --force-recreate new-api`。健康检查超出阈值时恢复回滚 Compose，并用同一命令重建旧实例。
4. 保留旧镜像、回滚 Compose 和数据库备份。应用回滚通常不恢复数据库；只有确认存在不兼容写入且再次获得授权后才恢复数据。

## 空窗与中断计时

- 优先使用应用 in-flight 指标或安全 drain。没有时，同时观察 Nginx 最终请求、应用完成日志和容器网络活动。
- 不把 `ESTABLISHED` 数量当作在途数量。使用 `ss -tinp` 检查收发队列、`lastsnd`/`lastrcv` 和字节变化；空闲 keep-alive 可以长期保持连接。
- 长 ASR、流式 TTS 或等待上游的非流式请求可能暂时没有网络数据。没有 in-flight 指标时明确这是概率性空窗，并采用保守静默期；不要写成严格归零。
- 在切换前做最后一次检查，并记录宿主机时区与 UTC 时间。优先从 Docker 事件记录旧容器停止时间；若只记录 Compose 开始和首次健康成功时间，结果标记为“可用性恢复上界”。
- 切换后按记录的时间窗口检查 Nginx 和应用 5xx，确认是否有客户端请求撞上窗口。

## 健康、SQLite 与管理面

- 容器没有 shell 或宿主机未映射端口时，从现有 Nginx 容器访问 `http://new-api:3000/api/status` 做内部就绪探测，不为健康检查临时改镜像或暴露端口。
- 先只读检查 `nginx -T` 的 `server_name`、`location` 和 `proxy_pass`。API 域名可能只转发 `/v1/`，其 `/api/status` 可能返回前端 HTML；使用实际管理域名或内部服务地址检查状态。
- 配置关闭的接口可能有预期的 403，例如未启用倍率公开时的 `/api/ratio_config`。先核对对应开关，再用相关数据库配置和真实计费结果验证，不把预期禁用误判为发布失败。
- 所有在线 SQLite 查询使用 busy timeout（例如 `.timeout 10000`）和有限重试。一次 `database is locked` 是瞬时竞争证据，不等于损坏；持续锁冲突仍需停止验收并诊断。
- 比较渠道、能力、选项、用户等应稳定计数；Token、日志及用量表可能在发布过程中因正常业务增长。记录时间点、解释增量，并按本次请求 ID 隔离验收写入。

## 火山语音最小验收

在生产真实请求已授权、默认音色和启用限额的专用测试 Token 已确认后，使用 `scripts/validate-volc-speech-production.py`。脚本必须：

- 不输出 Key/Token，不把凭据放入命令行参数；
- 通过公开 `/v1/models` 确认 `sxh-tts`、`sxh-asr`；
- 用 OpenAI 标准音色执行最小 TTS，再把生成的小音频提交给 ASR；
- 使用 `X-Oneapi-Request-Id` 精确查找两条消费日志；
- 核对正向计费、Token 用量变化、渠道/模型和正文未写入 `content`/`other`；
- 自动删除临时音频和响应。专用 Token 有并发时，Token 总增量可以大于本次日志合计，必须明确并发边界。

## 发布前清单

- [ ] 本地工作区干净，候选提交已合并。
- [ ] `VERSION`、发布日志和镜像标签一致。
- [ ] `go test -timeout 10m ./...` 通过。
- [ ] 相关 race、前端构建和 Docker 构建通过。
- [ ] 线上容器状态、镜像、启动时间和挂载已记录。
- [ ] 数据库备份已完成，完整性和 SHA-256 已验证。
- [ ] 旧镜像/二进制/Compose 可回滚。
- [ ] 已确认是否包含数据库迁移或新增环境变量。
- [ ] 候选镜像已在远端加载并核对哈希，切换窗口内不再下载或构建。
- [ ] 已定义连续空窗、最大等待和回滚阈值，并准备 Nginx/连接/应用在途请求监控。
- [ ] 已确认是否存在安全 drain 入口；没有时接受单实例切换的短暂竞争窗口，不临时并行挂载同一 SQLite。
- [ ] 候选 Compose 已验证且自动回滚命令可执行。

## 发布后清单

- [ ] 新容器镜像、版本和提交正确。
- [ ] 数据挂载未变化。
- [ ] 健康和状态接口正常。
- [ ] 管理端渠道列表、模型列表和定价读取正常。
- [ ] 最小真实请求成功，计费与日志正确。
- [ ] 最近日志无数据库、迁移、鉴权或持续 5xx。
- [ ] manager 容器与数据未变化。
- [ ] 已记录实际停机时间；若没有旧容器停止时间，则明确标记为恢复上界。
- [ ] 已记录空窗判定依据、最后一次在途检查和旧实例停止至新实例健康的秒数。
- [ ] 已按切换时间窗口检查 Nginx 和应用 5xx。
