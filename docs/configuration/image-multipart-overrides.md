# 图生图 multipart 参数删除

OpenAI 兼容适配器的 `/v1/images/edits` multipart 请求支持渠道参数覆盖中的
`delete` 操作。配置放在目标渠道的参数覆盖中，渠道选择自然限定规则作用范围。
例如，仅删除映射后 `gpt-image-2` 图生图请求的 `input_fidelity`：

```json
{
  "operations": [
    {
      "mode": "delete",
      "path": "input_fidelity",
      "logic": "AND",
      "conditions": [
        { "path": "upstream_model", "mode": "full", "value": "gpt-image-2" },
        { "path": "request_path", "mode": "full", "value": "/v1/images/edits" }
      ]
    }
  ]
}
```

这是配置示例，不会自动写入线上渠道。是否恢复出图仍需真实请求验证；该规则不处理上游余额、产能或协议故障。

## 支持范围

- JSON 继续使用原有参数覆盖逻辑。
- multipart 仅支持普通顶层字段删除；字段名只接受字母、数字、下划线和连字符，且不能以数字开头。不支持嵌套路径、通配符、设置、复制、改名或旧式键值覆盖。
- 删除字段会移除该字段的全部值；未删除的多值字段保持原值和顺序。条件匹配中单值是字符串，多值是数组。
- 不允许删除 `model`、`n`、`size`、`quality`、`prompt`、`stream`、`partial_images`、`image`、`mask`。文件不进入规则引擎，图片和 mask 继续由现有适配器处理。
- 全局或渠道请求体透传开启时，图像请求若同时配置参数覆盖会明确报错；使用规则前必须关闭透传。这个检查也适用于 JSON 图像请求。
- 先匹配每条操作的条件，再检查 multipart 支持范围。未命中的其他接口操作会跳过；命中的不支持操作会明确报错。非法规则结构和旧式键值覆盖仍会报错。
- 条件中的 `model`、`upstream_model`、`original_model`、`request_path` 使用服务端上下文，即使客户端提交同名字段也不能覆盖；服务端缺少这些信息时也不会回退到客户端字段。其他已有服务端上下文字段同样优先于同名表单字段。普通字段条件按操作顺序观察前面删除后的值。
- 每次适配器转换从原表单复制字段，不修改原始表单；切换渠道时重新应用目标渠道规则。每次尝试重置请求长度和删除审计，并恢复原始 Content-Type；转到透传渠道时使用原始请求体的实际长度和 multipart boundary。
- 删除审计写入现有参数覆盖审计字段，仅包含被删除字段的名称。

不要通过删除其他自定义计费字段来改变计费含义；本功能不提供计费字段转换或重新估算。
