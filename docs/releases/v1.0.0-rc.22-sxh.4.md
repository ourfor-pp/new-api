# v1.0.0-rc.22-sxh.4 候选版本日志

## 版本目标

本候选版本在 `sxh/rc22` 的火山 Seed-TTS 2.0 与极速 ASR 基础上补齐字幕和时间轴能力。客户端继续使用业务模型 `sxh-tts`、`sxh-asr`，服务端通过渠道模型映射解析到底层模型，适配器不依赖业务模型名。

本版本只生成候选镜像，不自动部署生产，也不修改数据库或渠道。

## 新增功能

- ASR `verbose_json` 支持 `segment`、`word` 两种时间戳粒度，可同时请求。
- ASR 开放 UTF-8 SRT 和 WebVTT 输出。
- TTS 支持 `stream_format=sse`，以 `speech.audio.delta` 流式返回 Base64 音频块，并以 `speech.audio.done` 结束。
- TTS SSE 可选返回 `sxh.speech.subtitle.delta` JSON 时间轴和 `sxh.speech.subtitle.done` 汇总事件。
- TTS 字幕汇总事件可同时携带 SRT 和 WebVTT。
- 语音审计日志增加时间戳粒度、字幕格式、句数、字词数和 TTS 用量来源。
- 客户端文档增加 `sxh-tts`、`sxh-asr` 的 cURL、OpenAI SDK 和 TypeScript SSE 示例。

## 兼容性

- 现有 TTS MP3、Opus、PCM 裸音频流保持原响应协议。
- 现有 ASR `json`、`text`、默认 `verbose_json` 保持兼容；未指定粒度时仍只返回句段级时间戳。
- 时间戳和字幕不新增计费项，不改变 TTS 字符计费和 ASR 时长计费。
- 火山聊天、图像、V1 TTS 及其他渠道路由不变。
- 未修改的 OpenAI SDK 可继续使用裸音频；TTS 字幕扩展事件需要业务客户端自行解析 SSE。

## 修复与防护

- multipart 同时兼容 `timestamp_granularities[]` 和不带方括号的重复字段。
- 字幕参数与不兼容的响应格式组合会在请求进入上游前返回明确的 `400`。
- TTS 只在请求字幕时启用火山 `audio_params.enable_subtitle`。
- 火山先返回空句子预告、随后返回有效字词时，只保留最终有效事件。
- 音频成功但无有效字幕时返回 `available:false`，不伪造时间轴、不判为质量失败。
- TTS 输出首字节后发生上游中断时发送 SSE error 事件、禁止渠道重试并标记部分流失败。
- SRT/VTT 使用火山原始句子文本和时间范围，不拆分标点或数字，不做均分、纠偏或 forced alignment。

## 计费与审计

- TTS 优先使用合法的火山 `usage.text_words`；成功结束但缺少用量时回退到输入 Unicode 字符数。
- ASR 继续按火山实际音频时长校正，每分钟换算 1000 个内部计费单位。
- 字幕格式不重复计费。
- 日志不记录 APP Key、完整合成文本、音频内容或 SRT/VTT 正文。

## 已知限制

- 不支持标准、闲时、实时 WebSocket 或异步长文件 ASR。
- 不支持长文本 TTS、双向 TTS、声音复刻、阿里语音和对象存储任务接口。
- 不对火山时间轴做合理性检测或修正。
- TTS SSE 已开始输出后不能切换备用渠道，客户端必须丢弃不完整结果后重新发起请求。
